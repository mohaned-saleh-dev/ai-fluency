1. Executive summary

1.1 Purpose

This document defines the design enhancements required to bring the Tamara AiQ Fluency Assessment from an internal prototype to a pilot-ready product experience. It covers visual identity application, information architecture, screen specifications, component standards, motion, accessibility, and a phased rollout plan for design and front-end implementation.

1.2 Design problem statement

The current UI (static/brand.css, static/index.html) correctly uses Tamara tokens but applies them at maximum intensity: full-bleed purple gradients, deck-style shadows, uppercase CTAs, six dimension chips during chat, and a dense results dashboard. For a ~10-minute reflective conversation, this creates:

  • Cognitive overload — users process branding and assessment content at the same time.
  • Anxiety — visual language feels like a test, launch event, or sales page.
  • Distrust of intent — “Internal preview” + spectacle undermines the “reflection, not performance review” message.
  • Poor scan hierarchy — everything competes at font-weight 800.
Design north star
Tamara AiQ should feel like a thoughtful internal tool: calm surfaces, one primary action per screen, lavender as punctuation — not wallpaper. The chat is the hero; brand is present but quiet.

1.3 What we are not doing

  • Adopting AISA’s dark mode, neon accents, or certification/leaderboard energy.
  • Replacing Tamara Visual Identity 2025 — we refine application, not rebrand.
  • Adding decorative “slide numbers,” marketing stats, or social-proof tickers on the assessment path.

5. Information architecture

5.1 Site map (participant path)

1. Welcome → 2. About you (level, family, intent) → 3. Chat → 4. Scoring → 5. Results story (slides) → 6. Full report + PDF

5.2 What to hide from participants

  • Dimension codes D1–D6 during chat (admin/orchestrator only).
  • Weight percentages on first results view (show on “full breakdown”).
  • “Internal preview” badge in production pilot (replace with “Tamara internal” or remove).
  • Integrity / paste flags (admin only in pilot).

5.3 Content hierarchy per screen

Each screen gets one primary question in the user’s mind:

  1. Should I start? → value + time + Begin
  2. Who am I for this run? → level, family
  3. What do I say? → single interviewer message + reply box
  4. Is it working? → scoring progress
  5. How did I do? → score + persona
  6. What next? → gaps + actions + PDF

6. Screen specifications

Layout

  • Full viewport: --surface-mist background.
  • Centered card max-width 480px, white, elevation 1.
  • Tamara lockup top; no gradient bar.

Content (max)

Remove from Screen A: 3 bullet expect list, bookmark URL warning, level/family dropdowns, “Internal preview” badge.

6.2 About you (Screen B) Phase 1

  • Progress: dot 2 of 3.
  • Fields: Level (select), Job family (select).
  • Optional: Intent — single select (“Growing in my role”, “Leading a team”, “Employer asked”, “Curious”).
  • Footnote: one line privacy — “Transcript stored for L&D; don’t paste customer data.”
  • CTA: “Start chat”.

6.4 Scoring wait (Screen D) Phase 2

Full-screen white/mist overlay after user taps End session.

  • Headline: “Reviewing your conversation…”
  • Sub: “This usually takes under a minute.”
  • Indeterminate or staged progress bar (lavender).
  • No “challenge a friend” in internal pilot.
  • On failure: calm retry button; preserve Tamara tone.

6.6 Full report (Screen F) Phase 1

Evolve current report-onepage — simplify first paint:

  1. Hero row: Score + band + 2-line summary only.
  2. Accordion or tabs: Dimensions | Coaching | Learning links.
  3. Remove on first load: Radar chart (optional expand), benchmark scale if cohort < 30.

6.7 End session modal Phase 1

  • Keep modal pattern; reduce stat grid unless readiness API returns meaningful breadth.
  • Title: “Finish and see your summary?”
  • Buttons: “Keep chatting” (secondary) · “See my summary” (primary).
  • Loading state inside modal → transition to Screen D.

7.2 Form controls

  • Select: white bg, --border, focus ring 3px lavender 20% alpha.
  • Textarea: min-height 48px; radius 12px; no 2px heavy purple border default.

7.3 Chips / pills

  • Meta chips (intro): grey bg #f4f3f8, ink-muted text.
  • Active phase: lavender outline, not filled purple chip farm.

7.4 Score display

  • Composite: 48–56px numeral, ink color — not gradient fill.
  • Dimension row: label left, bar center, score right — one row per dimension in full report.
  • Avoid red/green score coloring; use lavender bar fill only.

7.5 Empty / loading / error

StateTreatment
LLM typingThree soft dots, lavender — “Thinking…”
API errorRose-tinted banner, plain language, retry
Session endedNeutral message + link to start new

8. Motion & interaction

  • Message in: fade + 4px translateY, 200ms ease-out.
  • Slide transition: 250ms horizontal fade (results story).
  • No: pulse animations on “View results” link; parallax; hero number count-up (optional subtle only on slide E2).
  • Respect prefers-reduced-motion: disable transforms.

14. Phased delivery

Phase 1 — Calm foundation 1–2 weeks

  • White/mist page background; remove full-bleed gradient
  • White chat header; light participant bubbles
  • Sentence-case buttons; reduce font-weight 800 usage
  • Split intro: Welcome + About you
  • Hide dimension chips from chat; phase label only
  • Simplify results hero (score first; accordion for rest)
  • Remove “Internal preview” badge for pilot build

Phase 2 — Journey polish 2–3 weeks

  • Scoring wait screen (Screen D)
  • 5-slide results story (Screen E)
  • Persona card on slide E2
  • Intent capture on Screen B
  • WCAG audit fixes

Phase 3 — Refinement ongoing

  • Internal benchmark chart when cohort sufficient
  • Admin UI calm pass
  • Arabic RTL exploration
  • Figma component library synced to code tokens

Summary
The enhancement is not a rebrand — it is restraint. Tamara AiQ should read as a trusted internal conversation tool: white space, lavender accents, progressive disclosure, and copy that lowers stakes. Implement Phase 1 before any new assessment features; visual calm is a pilot requirement, not polish.
